3. GENERATE CODE — HX-{id} / DX-{id}
────────────────────────────────────────────────────────────────────────────────

UI cũ (Thymeleaf mock):
  th:text="${'HX-' + b.id}"
  th:text="${'DX-' + m.id}"
  → Chỉ ghép chuỗi ở view, KHÔNG lưu DB, KHÔNG phải source of truth.

Chuẩn BE (đã làm trong 2 ServiceImpl), bám pattern ConsignmentServiceImpl
(KG-{id}) / SaleNews (TD-…) / Inspection (KD-…):

  BrandServiceImpl
    private static String generateCode(Long id) {
        return "HX-" + id;
    }

  VehicleModelServiceImpl
    private static String generateCode(Long id) {
        return "DX-" + id;
    }

Luồng create:
  1) setCode(temporaryCode())     // TMP-{uuid12} — thỏa NOT NULL + UNIQUE trước khi có id
  2) save()                       // Hibernate cấp id
  3) setCode(generateCode(id))    // HX-5 / DX-8 — mã thật
  4) transaction commit           // ddl-auto update sẽ flush code mới

Tại sao private trong ServiceImpl?
  - Mã là quy ước hệ thống, không cho Controller/HTML tự ghép
  - Response trả field code đã lưu → list/view dùng ${item.code} thay vì 'HX-'+id
  - Đổi prefix sau này chỉ sửa 1 chỗ (generateCode)

Khác VehicleType.code:
  VehicleType: user nhập / normalize (SUV_MINI)
  Brand/Model: hệ thống sinh theo id — form Request KHÔNG có field code

5. ÁNH XẠ CỘT UI → ENTITY / RESPONSE
────────────────────────────────────────────────────────────────────────────────

Màn Hãng xe:
  Mã           → Brand.code          (HX-{id})
  Tên hãng     → Brand.name
  Số dòng xe   → BrandResponse.modelCount  (= countByBrandId)
  Trạng thái   → Brand.status
  Ghi chú      → Brand.note

Màn Dòng xe:
  Mã           → VehicleModel.code   (DX-{id})
  Hãng xe      → brand.name (join)
  Dòng xe      → VehicleModel.name
  Trạng thái   → VehicleModel.status
  Ghi chú      → VehicleModel.note
  Filter brand → search(..., brandId)  (deep-link từ brand view)
